# Проектирование очереди ожидания книг — Информационная система библиотеки

## 1. Цель документа

Описать архитектуру и бизнес-логику системы очереди ожидания книг,
включая статусы бронирований, сроки действия резервов, механизмы продвижения
и обработку ключевых сценариев.

## 2. Статусы бронирования

| Статус      | Значение |
|-------------|----------|
| `PENDING`   | Читатель в очереди, экземпляр ещё не выделен (запрос зарегистрирован, свободных экземпляров нет). |
| `ACTIVE`    | Экземпляр зарезервирован за читателем; читатель должен «забрать» (оформить выдачу) в течение срока. |
| `FULFILLED` | Резерв исполнен: экземпляр выдан читателю (переход в выдачу). |
| `CANCELLED` | Читатель отменил бронирование. |
| `EXPIRED`   | Срок действия резерва истёк, экземпляр передан следующему читателю (или возвращён в доступность). |

## 3. Срок действия резерва

- Срок: **48 часов** (`RESERVATION_PERIOD = 48h`).
- Для статуса `ACTIVE` поле `expires_at = reserved_at + 48h`.
- Для `PENDING` срок может задаваться при регистрации в очереди
  (`queue_date + 48h`) либо фиксироваться при активации — в проекте принимается
  активация с моментом резервирования экземпляра.

## 4. Механизм перехода к следующему читателю

- Очередь учитывает порядок регистрации (`queue_date ASC`, при равенстве — `id ASC`).
- При событии «экземпляр стал доступен» (возврат из `ISSUED`) или после отмены/истечения
  текущего резерва система выбирает первого подходящего читателя из очереди:
  1. Ищет первую запись в очереди для книги с статусом `PENDING` (или переводит `ACTIVE` → следующему).
  2. Статус бронирования → `ACTIVE`, экземпляр → `RESERVED`.
  3. `expires_at = now + 48h`.
  4. Остальные записи остаются в очереди со своим порядком.

## 5. Обработка отмены бронирования

- Читатель отменяет своё бронирование (`CANCELLED`).
- Если бронь была `ACTIVE` (экземпляр зарезервирован за читателем), эквивалентно
  освобождается экземпляр (`AVAILABLE`).
- Далее выполняется продвижение следующего читателя из очереди; если очередь пуста —
  экземпляр остаётся доступным.

## 6. Обработка истечения срока резерва

- Если бронь `ACTIVE` и `now > expires_at` → статус `EXPIRED`.
- Экземпляр возвращается в доступность (`AVAILABLE`).
- Далее продвигается следующий читатель в очереди.

## 7. Защита от одновременного резервирования

- Запрет дублей: `UNIQUE (reader_id, book_id, status)` — читатель не может иметь
  одновременно две активные (`PENDING`/`ACTIVE`) брони на одну и ту же книгу.
- Оперативная проверка статуса экземпляра (`AVAILABLE` → `RESERVED` → `ISSUED`).

## 8. Сценарии

### Сценарий 1: очередь из одного человека
- Читатель А запросил книгу, свободных экземпляров нет → бронь `PENDING`.
- Возврат экземпляра → продвижение: А → `ACTIVE`, экземпляр `RESERVED`, срок 48 ч.
- А не забрал в срок → `EXPIRED` → очередь пуста → экземпляр `AVAILABLE`.

### Сценарий 2: очередь из нескольких человек
- A, B, C встали в очередь (в порядке регистрации).
- Возврат → A (`ACTIVE`, 48 ч, `RESERVED`); B и C — дальше в очереди.
- A истёк/отменён → продвижение B → B `ACTIVE`; C остаётся queued.

### Сценарий 3: отмена бронирования первым читателем
- A — первый в очереди, бронь `ACTIVE` (экземпляр `RESERVED`).
- A отменил → бронь `CANCELLED`, экземпляр освобождается → продвигается B → B `ACTIVE`, новый срок 48 ч.

### Сценарий 4: истечение срока резерва
- A — `ACTIVE`, `expires_at` в прошлом, не использован.
- Система переводит бронь в `EXPIRED`, экземпляр → `AVAILABLE`, продвигает следующего.

### Сценарий 5: возврат книги при пустой очереди
- Возврат → экземпляр `RETURNED` → `AVAILABLE`; очередь пуста → доступен всем.

### Сценарий 6: одновременная попытка нескольких получить последний экземпляр
- Единственный экземпляр `AVAILABLE`; A и B в очереди.
- Обработка выдачи: сначала получает A (по порядку) → экземпляр `ISSUED`;
  B остаётся в очереди (своё место).

## 9. Алгоритм работы очереди

1. Чтение запроса читателя.
2. Если экземпляр `AVAILABLE` → выдача (issue) напрямую.
3. Иначе → добавить читателя в конец очереди (`PENDING`).
4. На событии «возврат экземпляра» → продвигать голову очереди.
5. На отмену/истечение → продвигать следующего или освобождать экземпляр.

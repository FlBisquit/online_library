## 1. Права доступа и IDOR

Проверены все маршруты: `/api/reports/books/[export]`, `/api/action-log/`,
`/api/users/`, `/api/users/<pk>/`, `/api/issues/<pk>/return|mark-lost/`,
`/api/reservations/<pk>/[cancel]`, `/api/books/<book_id>/queue/…/position/`,
`/api/readers/<pk>/issues/`, `/api/auth/me/reservations/`, `/api/readers/search/`,
`/api/issues/`, каталог и JWT-эндпоинты.

- **IDOR-1 — читателю отдаётся `total` (число желающих в очереди)** при
  `GET /api/books/<book_id>/queue/`, `views.py:539,557,568`. Чужие позиции и email
  не раскрываются, но агрегат виден.
  - Серьёзность: **low**.
  - Статус: **Отклонено, потому что** это прямо разрешённая комментарием в коде
    агрегированная справка; объектная проверка `views.py:551-570` гарантирует,
    что читатель видит только свою позицию. Если политика конфиденциальности
    изменится, `total` нужно убрать для не-staff.

- **Реальный IDOR не найден**: у каждого эндпоинта есть роль-гейт
  (`IsLibrarianOrAdmin`, `IsAdmin`, `IsCatalogEditor`) либо объектная проверка
  `request.user.id == owner.id` (`_can_access_reservation`, `_can_access_reader`,
  проверки в `ReaderIssuesView` и `MeReservationsView`).
  - Серьёзность: **неприменимо**.
  - Статус: **Отклонено, потому что** проверка всех перечисленных маршрутов
    подтвердила отсутствие доступа к чужим объектам; регрессионные тесты есть в
    `backend/library/tests/test_permissions.py`.

- **Расхождение документации с кодом (не уязвимость)**: старый текст
  `docs/AI_REVIEW.md` утверждал, что читатель может закрывать свою выдачу и что
  `reader_id` при выдаче берётся из JWT. По факту возврат — только staff
  (`views.py:502`), а `reader_id` для выдачи берётся из тела запроса
  (`views.py:424-439`), это осознанное действие библиотекаря.
  - Серьёзность: **low**.
  - Статус: **Исправлено в тексте этого документа** (текущая правка; код не
    менялся): неверные утверждения удалены.

## 2. JWT

Настройки: `backend/config/settings.py:119-127`, приложение
`rest_framework_simplejwt.token_blacklist` подключено в `settings.py:32`,
эндпоинты `/api/token/`, `/api/token/refresh/`, `/api/token/blacklist/`.

- **JWT-1 — слабый/плейсхолдерный `SECRET_KEY`.** Хардкод в `settings.py` убран,
  но `backend/.env.example:2` содержит
  `SECRET_KEY=change-me-to-a-long-random-secret-key`, а локальный `backend/.env`
  (в git не входит) — `django-insecure-local-development-secret-key`. При HS256
  known secret позволяет подделать токен, включая admin.
  - Серьёзность: **high** при деплое с этими значениями.
  - Статус: **Исправлено (коммит `c7e0a6a`)** только в части `settings.py`:
    дефолт удалён, `SECRET_KEY=str` без значения — приложение откажется стартовать
    без переменной. **Не исправлено (открыто)**: плейсхолдер в `.env.example`.
    Требуется сгенерировать случайный секрет (≥32 байт) и запретить значения `change-me*`
    / `django-insecure*`; в проде секрет передавать только через окружение.

- **JWT-2 — не работает лимит на `/api/token/`.** В `backend/library/urls.py:9`
  написано `TokenObtainPairView.throttling_class = ScopedRateThrottle`; в DRF
  атрибут называется `throttle_classes`. В рантайме у view активны только
  `AnonRateThrottle`/`UserRateThrottle`, поэтому `DEFAULT_THROTTLE_RATES["token"] =
  "10/min"` (`settings.py:115`) не применяется; логин ограничен общим `anon 60/min`.
  - Серьёзность: **medium**.
  - Статус: **Не исправлено (открыто)**. Попытка настроить лимит есть, но она
    неисправна; нужно `throttle_classes = [ScopedRateThrottle]`.

- **JWT-3 — срок, blacklist и содержимое токена.** Access — 15 минут, refresh —
  7 дней, `ROTATE_REFRESH_TOKENS=True`, `BLACKLIST_AFTER_ROTATION=True`; тест
  ротации и blacklist в `test_auth.py:55-59`. Кастомного токен-сериализатора нет:
  в JWT нет ролей, `groups`, `is_staff`; роли читаются из БД через
  `Reader.has_role()`, поэтому смена роли действует сразу.
  - Серьёзность: **неприменимо** (замечаний нет).
  - Статус: **Исправлено (коммиты `9238407`, `c7e0a6a`)** — blacklist/rotation и
    15-минутный access lifetime соответственно.

- **JWT-4 — access-токены не отзываются при logout.** Это стандартное поведение
  SimpleJWT: в blacklist попадает только refresh.
  - Серьёзность: **low**.
  - Статус: **Отклонено, потому что** это осознанный компромисс JWT: срок access token
    ограничен 15 минутами, а отзыв refresh реализован. Мгновенный отзыв access
    потребовал бы отдельного механизма и отдельной задачи.

- **JWT-5 — заблокированный пользователь.** `Reader.is_active` (`models.py:74-77`)
  не даёт получить и обновить токены; тесты `test_auth.py:78-98`.
  - Серьёзность: **неприменимо**.
  - Статус: **Отклонено, потому что** поведение проверено и является корректным.

## 7. DEBUG, ALLOWED_HOSTS, CORS, rate limiting

- **CFG-1 — `DEBUG=True` в локальном `backend/.env`.** Дефолт в `settings.py:9`
  безопасный (`False`), но локальный файл (не в git) включает DEBUG; вместе с
  VAL-1..VAL-3 это даёт 500 с traceback.
  - Серьёзность: **high** при деплое с текущим окружением.
  - Статус: **Исправлено (коммит `c7e0a6a`)** в части дефолта;
    **Не исправлено (открыто)** для локального `.env` — в проде нужно явно
    `DEBUG=False` и проверять это при старте.

- **CFG-2 — `::1` вместо `[::1]` в `.env.example:3` и локальном `.env:3`.**
  IPv6-хост loopback не совпадёт как паттерн.
  - Серьёзность: **low** (функциональный дефект, не дыра).
  - Статус: **Не исправлено (открыто)** — заменить на `[::1]`; никогда `*` в проде.

- **CFG-3 — CORS.** `CorsMiddleware` первым (`settings.py:40`),
  `CORS_ALLOWED_ORIGINS` из env с дефолтом только `http://localhost:5173`
  (`settings.py:129`), `CORS_ALLOW_ALL_ORIGINS` и `CORS_ALLOW_CREDENTIALS` не
  включены.
  - Серьёзность: **неприменимо**.
  - Статус: **Отклонено, потому что** конфигурация ограничена списком origin; не задавать `*`
    через env.

- **CFG-4 — rate limiting.** `AnonRateThrottle 60/min`, `UserRateThrottle 200/min`,
  scope `token 10/min` (`settings.py:108-116`). Scope `token` мёртв (см. JWT-2);
  регистрация ограничена только общим `anon 60/min`.
  - Серьёзность: **medium**.
  - Статус: **Не исправлено (открыто)** — конфигурация есть, но не работает;
    после исправления `throttle_classes` желателен отдельный scope для
    `/api/auth/register/`, `/api/token/refresh/` и `/api/token/blacklist/`.

- **CFG-5 — отсутствуют `SECURE_SSL_REDIRECT`, `SECURE_HSTS_SECONDS`,
  `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE`.**
  - Серьёзность: **low**.
  - Статус: **Отклонено, потому что** API использует только JWT (`settings.py:100-102`),
    сессионные и CSRF-cookie не используются; TLS/HSTS заканчиваются на прокси.
    При необходимости — настройка инфраструктуры, не кода приложения.

## Итог

- **High:** плейсхолдер `SECRET_KEY` в `.env.example` (и локальный insecure ключ),
  `DEBUG=True` в локальном `.env`.
- **Medium:** неработающий scope `token` из-за `throttling_class`; 500 на
  невалидных query/body ID.
- **Low:** неполное экранирование CSV, `total` в очередях, IPv6-хост, отсутствие
  TLS-флагов, рассинхрон документации с кодом.
- **Не найдено:** SQL-инъекций, реального IDOR, утечек паролей/ролевых флагов
  через сериализаторы.
- Открытые пункты требуют отдельных коммитов; в этом документе они не отмечены
  как исправленные.

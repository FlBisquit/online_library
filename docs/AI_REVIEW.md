# AI Review — аудит безопасности онлайн-библиотеки

## 1. Инициативы аудита

- Проверено отсутствие секретов в исходном коде (выявлен hardcoded `SECRET_KEY` — исправлен, переведён в переменные окружения через `django-environ`).
- Проверено хранение JWT (SimpleJWT + `token_blacklist` для refresh-токенов).
- Проверена обработка идентификаторов пользователей из тела запроса.

## 2. Результаты

### 2.1 Секреты

- **Найдено:** `backend/config/settings.py` содержал hardcoded `SECRET_KEY`.
- **Исправлено:** ключ берётся из переменной окружения (`backend/.env`, пример — `backend/.env.example`).
- **Рекомендация:** в продакшене задавать сильный секрет через переменные окружения.

### 2.2 JWT и отзыв refresh-токенов

- **Найдено:** refresh-токены без отзыва.
- **Исправлено:** включён `TokenBlacklist` (`ROTATE_REFRESH_TOKENS`, `BLACKLIST_AFTER_ROTATION`).
- Проверено: refresh после blacklist возвращает `401`.

### 2.3 Идентификаторы пользователя

- **Правило:** идентификатор пользователя берётся из проверенного JWT-токена, а не из тела запроса.
- **Статус:** выдача выполняется от имени аутентифицированного пользователя (service-уровень).

### 2.4 Конкурентные операции

- **Правило:** `transaction.atomic()` + `select_for_update()` до проверки доступности.
- **Статус:** реализовано в `library/services.py`; проверен race-тестом на MySQL.

### 2.5 Отчётность

- **Правило:** агрегация через SQL (ORM `.aggregate`/`.annotate`), CSV-экспорт.
- **Статус:** реализованы endpoints отчётов.

## 3. Выявленные риски

- `DEBUG=True` в dev-конфигурации — для продакшена требуется выключение.
- CORS: ограничен списком доверенных origin'ов.
- Reader self-service: читатель может закрывать свои выдачи; библиотекарь/администратор — любые.

## 4. Рекомендации

- Включить `DEBUG=False` и секреты через env для продакшена.
- Регулярно проводить аудит журнала действий.
- Ограничить failed login попытки (rate limiting) при необходимости.

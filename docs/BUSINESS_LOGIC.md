# Бизнес-логика — Информационная система библиотеки

## 1. Общие правила выдачи и возврата

- Один физический экземпляр одновременно может быть выдан **одному** читателю:
  - статус экземпляра `AVAILABLE` → после выдачи переводится в `ISSUED`;
  - после возврата — обратно в `AVAILABLE`;
  - одновременная выдача двух читателей на один экземпляр блокируется
    (проверка статуса + частичный уникальный индекс `issues (copy_id) WHERE status = 'ISSUED'`).
- Стандартный срок выдачи: `due_at = issued_at + loan_period` (по правилам библиотеки).
- Возврат: проставляется `returned_at` и статус `RETURNED`.

## 2. Процессы

### 1. Добавление новой книги в каталог

- **Условия начала:** операция выполняется библиотекарем с правами на каталог.
- **Входные данные:** `title`, `description`, `isbn`, `publication_year`, `publisher`,
  `authors[]`, `genres[]`.
- **Последовательность:**
  1. Валидация входных данных.
  2. Проверка отсутствия дубликата по `isbn` (UNIQUE).
  3. Создание записи в `books`.
- **Возможные ошибки:** дубликат ISBN — операция отклоняется.
- **Ожидаемый результат:** книга добавлена в каталог.

### 2. Добавление физических экземпляров книги

- **Условия начала:** книга существует в каталоге (`books`).
- **Входные данные:** `book_id`, `inventory_number`, `status` (по умолчанию `AVAILABLE`).
- **Последовательность:**
  1. Проверка существования книги.
  2. Проверка уникальности `inventory_number`.
  3. Создание записи в `book_copies`.
- **Возможные ошибки:** несуществующий `book_id`; дубликат инвентарного номера.
- **Ожидаемый результат:** экземпляр добавлен и доступен (`AVAILABLE`).

### 3. Регистрация читателя

- **Условия начала:** операция выполняется библиотекарем.
- **Входные данные:** `full_name`, `email`, `phone`.
- **Последовательность:**
  1. Валидация данных.
  2. Проверка уникальности `email`.
  3. Создание записи в `readers` со статусом `ACTIVE`, датой регистрации `registered_at = now`.
- **Возможные ошибки:** дубликат email.
- **Ожидаемый результат:** читатель зарегистрирован.

### 4. Поиск книги в каталоге

- **Условия начала:** аутентификация пользователя.
- **Входные данные:** параметры поиска (название, автор, жанр, ISBN).
- **Последовательность:** выполнение поиска по каталогу.
- **Возможные ошибки:** отсутствие совпадений.
- **Ожидаемый результат:** список найденных книг.

### 5. Просмотр доступных экземпляров

- **Условия начала:** запрос доступных экземпляров.
- **Входные данные:** `book_id` или поисковый запрос.
- **Последовательность:** выборка из `book_copies` с `status = 'AVAILABLE'`.
- **Возможные ошибки:** экземпляры отсутствуют.
- **Ожидаемый результат:** список доступных экземпляров (с инвентарными номерами).

### 6. Выдача книги читателю

- **Условия начала:** читатель существует и имеет статус `ACTIVE`; экземпляр имеет статус `AVAILABLE`.
- **Входные данные:** `reader_id`, `copy_id`.
- **Последовательность:**
  1. Проверить читателя (`ACTIVE`).
  2. Проверить экземпляр (`AVAILABLE`).
  3. Проверить отсутствие активной выдачи на экземпляр.
  4. Создать запись в `issues` (`issued_at = now`, `due_at = now + loan_period`, `status = 'ISSUED'`).
  5. Обновить экземпляр: `status = 'ISSUED'`.
- **Возможные ошибки:** экземпляр недоступен; читатель заблокирован.
- **Ожидаемый результат:** выдача создана, экземпляр вычтен из доступных.

### 7. Возврат книги

- **Условия начала:** существует активная выдача (`issues.status = 'ISSUED'`).
- **Входные данные:** `issue_id`, фактическая дата возврата (по умолчанию — текущая дата).
- **Последовательность:**
  1. Обновить выдачу: `returned_at = now`, `status = 'RETURNED'`.
  2. Обновить экземпляр: `status = 'AVAILABLE'`.
- **Возможные ошибки:** выдача не найдена или уже возвращена.
- **Ожидаемый результат:** экземпляр снова доступен.

### 8. Просмотр истории выдач

- **Условия начала:** аутентификация (сам читатель или библиотекарь).
- **Входные данные:** `reader_id`.
- **Последовательность:** выборка выдач читателя, упорядоченная по дате выдачи.
- **Ожидаемый результат:** список операций выдачи.

### 9. Продление срока пользования

- **Условия начала:** активная выдача; продление разрешено правилами (лимит, срок).
- **Входные данные:** `issue_id`, новый срок (`due_at`).
- **Последовательность:** обновление `due_at` у активной выдачи.
- **Возможные ошибки:** лимит продлений превышен; продление после истечения срока запрещено.
- **Ожидаемый результат:** срок выдачи продлён.

### 10. Обработка недоступных экземпляров

- **Условия начала:** читатель запрашивает книгу, экземпляры которой недоступны.
- **Входные данные:** `reader_id`, `book_id`.
- **Последовательность:**
  1. Проверка отсутствия активной брони у читателя на эту книгу.
  2. Создание бронирования: `status = 'PENDING'/'ACTIVE'`, `queue_date = now`, `expires_at = now + reservation_period`.
- **Возможные ошибки:** активная бронь уже существует.
- **Ожидаемый результат:** читатель встал в очередь.

## 3. Основные алгоритмы (последовательные)

### Алгоритм выдачи

1. Получить параметры выдачи: `reader_id`, `copy_id`.
2. Загрузить читателя → проверить `status = ACTIVE`.
3. Загрузить экземпляр → проверить `status = AVAILABLE`.
4. Проверить отсутствие активной выдачи на экземпляр.
5. Создать выдачу: `issued_at = now`, `due_at = now + loan_period`, `status = ISSUED`.
6. Обновить экземпляр: `status = ISSUED`.

### Алгоритм возврата

1. Загрузить выдачу → проверить `status = ISSUED`.
2. Обновить выдачу: `returned_at = now`, `status = RETURNED`.
3. Обновить экземпляр: `status = AVAILABLE`.

### Алгоритм бронирования при нехватке

1. При отсутствии `AVAILABLE`-экземпляров создать бронь (`PENDING`/`ACTIVE`) с датой и сроком.
2. При возврате экземпляра (статус `AVAILABLE`) бронь переводится в выдачу.
